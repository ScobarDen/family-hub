# Voice and text commands go through Workers AI and always end in a confirmed Command Draft

A Member can say or type what to do («напомни в пятницу в 19:00 оплатить интернет») in the bot or in the Mini App, and the app turns it into a record after the Member confirms. Everything runs on Cloudflare Workers AI through the `AI` binding, so there are no external keys and no new paid service: speech becomes text with Whisper (`@cf/openai/whisper-large-v3-turbo`), and text becomes a Command Draft with an LLM answering JSON against a schema. Model names live in `vars` (`AI_COMMAND_MODEL`, `AI_COMMAND_MODEL_FALLBACK`, `AI_SPEECH_MODEL`).

The model never creates anything. It returns a Command Draft, the shared pipeline in `packages/` validates it against the schema from `@family-hub/contract`, the Member sees a preview and taps «Создать», and the record is created by the same use case the Mini App form calls. «Изменить» opens that ordinary form with the draft's fields filled in. The prompt carries today's date, the Family's time zone and the lists of Pets and Members, so «в пятницу» and «Бьюику» resolve to a date and an id instead of a guess; a reference the model cannot resolve uniquely comes back as an ambiguity with candidates, never as a picked value. Destructive and Operator commands are not supported at all.

## Decisions

- **Entry points.** A text message to the bot and a voice message (`message.voice`, up to ~30 s) get a preview with inline buttons «Создать / Изменить / ×»; the Mini App records with a hold-to-talk microphone in the centre of the tab bar and posts the audio to the API. The webhook answers 200 at once and does the AI work in `ctx.waitUntil`, because a transcription plus an LLM call can outlast Telegram's webhook patience and a retried update would parse twice.
- **Audio never goes through base64 in our code.** Whisper's input accepts `{ body, contentType }`, so the Worker passes the stream from `getFile` or from the request body straight to the model; waiting on the model is not CPU time, which keeps a voice command inside the free plan's 10 ms. Measured on 2026-10-22: about 9 ms for 10 s of speech, a thin margin accepted for now; trimming (a shorter recording limit, the paid plan) waits until requests actually hit the limit.
- **Hold-to-talk, like Telegram.** Pressing the microphone starts recording, releasing sends, sliding off cancels. Vertical swipes are disabled for the duration of the hold so closing the Mini App does not fight the gesture. If the microphone is unavailable, the button opens the bot chat with `openTelegramLink`. Telegram's WebView keeps the microphone permission only until the Mini App is closed, on iOS, Android and Desktop alike, and the Mini Apps API has no way to ask for longer; the permission prompt swallows the hold that triggered it. So the first hold of every launch asks and records nothing, the next one records, and the stream stays open while the Mini App is on screen.
- **Primary LLM `@cf/meta/llama-3.3-70b-instruct-fp8-fast`**, the current model with documented JSON mode (`response_format: json_schema`); `@cf/meta/llama-4-scout-17b-16e-instruct` with `guided_json` is the fallback, tried when the primary answers that the model is gone. Cloudflare has retired models with two to three weeks' notice (Llama 3 / 3.1 on 2026-05-30), so the model is configuration, not code.
- **A schema miss is an ordinary outcome.** JSON mode can still fail («JSON Mode couldn't be met») or return something the schema rejects; the Member then gets «Не понял» with examples, not an error. A draft with missing required fields (no time, an unresolved Recipient or Pet) is shown without «Создать»: the Member picks a candidate from buttons or goes to «Изменить».
- **Budget: 30 commands a day per Family** (`AI_COMMANDS_PER_FAMILY_DAY`), counted from the Family's Command Drafts since 00:00 UTC, when the Neurons allocation resets. The 10,000 free Neurons a day belong to the whole account, not to a Family: a 10 s voice command with the primary model measured about 36 Neurons (Whisper ≈8, the LLM ≈28.5), so a 30 s one is about 55, and roughly 180–270 a day for all Families together. When Workers AI refuses for an exhausted allocation, the Member is told to create the record by hand today, with a link to the form.
- **A Command Draft is stored** in D1 until confirmed, dismissed or expired after 24 hours, because `callback_data` holds 64 bytes and the preview button must point at it (`cd:<action>:<draftId>`); the Mini App reaches it by `start_param` `cmd_<draftId>`. Expired drafts are removed by the 03:00 UTC maintenance.
- **Reminder first.** Event and Care Entry are later extensions of the draft schema, each with its own preview and form.
- **Tests stay offline.** The pipeline, the schema and the parsing of model answers are tested in the package against recorded model outputs; Workers AI sits behind an interface that the Worker harness replaces with a fake. Real models, real audio formats and the WebView microphone are checked by hand (`docs/smoke.md`).

## Considered Options

- **An external API (OpenAI, Deepgram, Google)** — better quality, but it needs a key, a card and a second vendor's limits.
- **Deepgram `nova-3` on Workers AI** for speech — accepts more encodings natively, but costs about ten times Whisper per minute (≈473 vs ≈47 Neurons).
- **Letting the model create records directly through tools** — one tap less, but a misheard date would silently land in the Family's calendar, and the record would bypass the use case and its policies.
- **A cheaper LLM (`@cf/qwen/qwen3-30b-a3b-fp8`, ≈12 Neurons a command)** — six times cheaper, but a reasoning model without documented JSON mode; revisit if the budget becomes the bottleneck.
- **Tap to start, tap to stop** — no conflict with the close swipe and friendlier to a mouse, but it is not how Telegram records voice, and Members expect the Telegram gesture.
