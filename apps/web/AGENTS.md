# apps/web

The Telegram Mini App: React 19 and Reatom v1001, shadcn on Base UI with Tailwind v4, a static build for GitHub Pages under `/family-hub/`.

## Shape

- MVVM on FEOD levels, as in the `frontend-mvvm` skill: a ViewModel `*.vm.ts` per screen, a passive `*.view.tsx` built with `reatomComponent`, data in `*.api.ts` / `*.model.ts`, a module's public API in `index.ts`, a README in every module that has a ViewModel. The role matrix in `vite.config.ts` decides who imports whom.
- `src/app/main.tsx` is the composition root: it builds the real Telegram wrapper, HTTP client and models and hands them down, and holds no logic of its own. Every «open this record» — a `start_param` deep link, a tap in the Feed or another module, «Изменить» on a Command Draft — goes through `app/opener.vm.ts`, which switches the module, waits for the session or a picked Pet where needed and calls the module's own «open by id». `app/prefetch.vm.ts` reads Today and the two tab-bar slot screens once sign-in returns, so they load in the background together with a deep link's target; other sections load when opened. Nothing imports `global` (`@feod/analyzer` forbids it even from `main.tsx`): `index.html` links `global/styles.css`, and `global/*.d.ts` augments Vite's ambient types. A browser global owned by a common entity is declared beside that entity's types (`window.Telegram` in `common/telegram/telegram.types.ts`), because `global` may not import from `common`.
- `common/` holds the shared entities: `telegram` (the Mini App wrapper, `telegram-mini-app` skill; its semantic `haptics` follow the map in [docs/haptics.md](../../docs/haptics.md)), `http-client`, `ui` (shadcn components, `Button`'s `isPending`: a spinner over the invisible label, disabled and `aria-busy`, on every form submit, the shared form shell, `PickerField` / `PickerInput`: every date and time field (the native picker under an icon and Russian text, «×» on optional ones), `LoadState`: a load failure with «Повторить», the shimmering `Skeleton` and the shapes each module builds its screen skeleton from (a section of rows, Today tiles, a photo grid, the `SectionLayout` head), `FailureBar`: where every module reports a change the server did not take, `ModalDialog`: every full-screen overlay (the photo viewer, the Command Sheet) as a native `<dialog>` opened with `showModal()` from the model's open state, so the page behind is inert, Escape reaches the model's close and focus returns to the opener, `CheckButton`: the one circle that completes a Task Occurrence or a Subtask wherever it is listed, `Revealed`: content that replaces a skeleton fades in (Today staggers its blocks), `slideScreens`: the View Transition the navigation runs for a push and Back, and a module for a record opened from its own list (the classes live in `global/styles.css`; motion is gated by `prefers-reduced-motion`, which falls back to opacity), and `SectionLayout`: the summary, one primary button and tabs that Pets, Goals, Recipes and Albums share), `sections` (each section's title, icon and its own icon colour), `format-date`, `format-money`, `format-count` (a number with its Russian plural), `photo` (Exif date and shrinking before upload, signed photo links, `SignedPhoto`: every signed image, which keeps its box with a placeholder when an expired link fails), `photo-attachments` (photos picked for a record before it is saved), `photo-viewer` (the full-screen viewer with its delete, which applies at once and rolls back into the module's failure bar (shown inside the viewer while it is open), pick and, where a module offers it, share; Telegram goes full screen while it is open), `voice-recorder` (the microphone behind «Сказать»), `live-updates` (the socket to the Family's Durable Object while the app is on screen, and a version per module that its lists read to refetch another Member's change, [ADR 0010](../../docs/adr/0010-live-updates-through-a-family-durable-object.md)), `device-cache` (the last loaded data kept in Telegram DeviceStorage, or in memory where it is missing: `withDeviceCache` on a module's `withAsyncData` `data` atom with a key, the contract schema, a version and optionally `cachedPart` (what of the state to keep; `undefined` keeps the earlier copy), dropping what does not parse, an older version or anything older than 30 days; `keepFor` clears it for another Member or Family and `clear` for a stranger, [ADR 0012](../../docs/adr/0012-screens-render-from-a-device-cache-before-sign-in.md)), `state` (`detached` for a command the View fires without its promise, `Slide` for a change that slides the screen, `instantly` by default, `readOnly` for an atom handed out to read, `reatomFailure` for a failed command's text, `reatomOptimistic` for a change shown at once and rolled back with `withRollback` + `withTransaction` when the server refuses it, and `reatomRollbackFailure` for the failure bar's words: the caller's own for a refusal, «Нет связи, не сохранилось» when the request got no answer), `records` (replacing or dropping a record by id in a loaded list, and `rolledBack` / `rolledBackById`: a rollback that undoes only the records its change touched, so a change made meanwhile stays), `form` (refilling a Reatom form without its `reset`, which aborts the next submit, the «server refused the submit» message, and `reatomEditableRecord`: a form that creates a record, edits one or, given `valuesOfDraft`, starts from a Command Draft, with its saving flags, the draft settled once it is saved and Telegram's closing confirmation while the form on screen has unsaved changes (`confirmClosingWhileDirty`, held by `FormShell` and the care form); a module's form only maps values from the record, from the draft and into a change, and creates and updates).

## Rules

- **State and async are Reatom.** Loading, caching and optimistic updates with rollback use Reatom async (`withAsyncData`, `withCache`) in `.api` / `.model`. Forms are `reatomForm` bound to shadcn `Field*` through a thin adapter over `bindField`. Routing is the Reatom router on pathname under the `/family-hub/` base.
- **reactuse** holds only ephemeral DOM state that lives and dies with one View, so it is imported only in `*.view.tsx`. Anything a ViewModel reads, anything that outlives an unmount or touches async, validation, the URL or storage is Reatom.
- **Server calls** go through `common/http-client`: every response is parsed with its Zod schema from `@family-hub/contract`, which is the only type link to `apps/api` (the Worker's app type cannot be imported: both apps alias `@/` and the Worker leans on Cloudflare globals). The client keeps the session token in memory, holds every request made before sign-in until the token arrives (screens drawn from the device cache load at once; only the calls that carry initData pass `withoutSession`), attaches it and renews it when the app comes back on screen with a token older than 12 hours ([ADR 0013](../../docs/adr/0013-the-session-token-renews-while-the-app-stays-open.md)); any 401 flips `isSessionLost`, which shows «перезапустите приложение».
- **Telegram** is reached only through `common/telegram`.
- **UI**: shadcn on Base UI — custom triggers use `render`, not `asChild`. Components land in `common/ui` (aliases in `components.json`). Theme colours come from Telegram `themeParams`: `telegram-web-app.js` keeps the `--tg-theme-*` and safe-area variables current, and `global/styles.css` maps them onto the shadcn variables with fallbacks. Charts are shadcn charts.
- **Icons** are lucide only, imported one by one; the curated set for Savings Goal covers lives in the goals module's `goals.config.ts`. Emoji appear only in user text and bot messages.
- **tsconfig** keeps `paths` without `baseUrl`, whatever the shadcn guide says: `baseUrl` switches off the type-aware lint and type-check in Vite+.
- **React Compiler** stays off until its compatibility with `reatomComponent` is verified.
- **Dates** use Temporal (`temporal-dates` skill); user-facing text is Russian.

## Tests

ViewModels and models are unit-tested with Vitest, isolated per test through the Reatom context (`reatom-testing` skill), with a fake transport and a fake `common/telegram`: the real `common/http-client` and module `.api` run over a fake `fetch` that answers with shapes typed by `@family-hub/contract`, so the token, schema parsing and 401 handling are covered too. Wait for an async outcome with `vi.waitFor` on what the View reads, not with sleeps. Assert what the View receives: screen state, optimistic updates and rollbacks, 401 handling. Component tests and Storybook are out of scope for now.
